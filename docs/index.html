01 / COMPRENDER

Un clúster dentro de tu Mac.

Un servicio de Compose crea un contenedor. Jupyter ejecuta el driver; el master asigna recursos; los executors de los workers hacen las tareas. Todos están en un mismo portátil, no en máquinas físicas independientes.

Recomendado para empezar: master, worker 1 y Jupyter.

Añade el worker 2 para observar el reparto de tareas entre dos procesos ejecutores.

Mapa de servicios · Spark 4.0.1

1 worker · 2 tareas simultáneas · límite conjunto de 4,5 GiB

Los límites no son consumo fijo. Cada worker ofrece 1 GiB de heap Spark dentro de un contenedor limitado a 2 GiB. Abrir el esquema completo ↗. En móvil, desplaza el esquema horizontalmente.

02 / PREPARAR

Antes del primer arranque.

Instala Docker Desktop para Apple Silicon

Descarga la variante para Apple Silicon desde Docker, abre la aplicación y espera a que el motor esté listo. No necesitas instalar Java, Python, Spark ni Hadoop en macOS.

Asigna recursos y deja margen a macOS

Para comenzar: 8 GB de RAM y 4 CPU en Settings → Resources. Para dos workers puedes usar 10 GB y 6 CPU si el ejercicio lo necesita. Reserva unos 10 GB de disco libre. Son orientaciones, no una garantía para cualquier volumen de datos.

Descarga el proyecto en una carpeta local

Usa una carpeta fuera de iCloud Drive. Con Git instalado:

Terminal · carpeta del proyecto
mkdir -p ~/Proyectos
cd ~/Proyectos
git clone https://github.com/iesataulfoargentasor/sistemas-big-data-spark-arm64.git
cd sistemas-big-data-spark-arm64

Si prefieres el ZIP, descomprímelo y abre Terminal en la carpeta que contiene compose.yaml. Su nombre normalmente termina en -main; utiliza el nombre real. Git puede solicitar las herramientas de línea de comandos de Apple.

Comprueba Docker y detén el otro stack

Terminal · carpeta del proyecto
docker version
docker compose version

Debe aparecer Client y Server. Utiliza Compose 2.20 o posterior. Detén el otro laboratorio desde Docker Desktop: los stacks comparten algunos puertos. No hace falta borrarlo.

Todos los servicios de esta variante son ARM64. No necesitas activar Rosetta para ejecutarlos.
03 / DESPLEGAR

De la carpeta al clúster.

Construye la imagen ARM64

Terminal · carpeta del proyecto
bash preparar.sh

Solo la primera preparación necesita descargar dependencias. El asistente crea .env con tu UID/GID; conserva un archivo existente.

Arranca y comprueba el modo elegido

Terminal · carpeta del proyecto
bash iniciar.sh ligero
bash comprobar.sh

La selección del mapa actualiza estos comandos. Para clase, usa bash iniciar.sh clase. La prueba detecta el número de workers y debe terminar con "resultado": "OK" y "arquitectura": "aarch64".

Guarda el cuaderno antes de cambiar de modo. iniciar.sh recrea los contenedores de este proyecto. Se conservan los archivos de workspace, pero terminan las sesiones en memoria.

05 / TRABAJAR

Ejecuta, guarda y vuelve mañana.

En Jupyter, abre notebooks/01_Primer_cluster.ipynb, guarda una copia y ejecuta sus celdas. Usa spark://spark-master:7077; cambiar a local[*] dejaría de utilizar los workers.

Todos comparten /workspace, que corresponde a workspace/ en tu Mac. Ejecuta una aplicación Spark a la vez y termina con spark.stop() antes de iniciar otra.

Parar sin borrar archivos

Terminal · carpeta del proyecto
bash parar.sh

Reanudar el laboratorio

Terminal · carpeta del proyecto
bash iniciar.sh ligero

El nombre que verás en Docker Desktop es spark-aula-m4. Se mantiene el nombre interno de la versión validada. No ejecutes a la vez una copia anterior con ese mismo nombre.

06 / EVIDENCIA

Probado en un Mac M4.

  • Construcción ARM64 y arranque con uno y dos workers.
  • Python aarch64 en driver y executors; tareas ejecutadas en los workers.
  • Agregación CSV: ES = 30 y FR = 12; escritura y lectura de Parquet.
  • Cuaderno completo ejecutado sin errores y cambio de dos workers a uno.

Pruebas realizadas el 28 de octubre de 2026 con datos pequeños. No es un ensayo de rendimiento para grandes volúmenes.

07 / AYUDA

Si algo no arranca.

Docker no responde

Abre Docker Desktop y espera a que termine de arrancar. Ejecuta docker version: debe mostrar la sección Server.

Un puerto ya está ocupado

Detén el stack de la otra asignatura. En Spark puedes cambiar los puertos publicados en .env; en Big Data, en compose.yaml. Mantén los puertos internos y los nombres de servicio.

No puedo guardar archivos

Usa una carpeta local, compartida con Docker y escribible por tu usuario. Ejecuta preparar.sh sin sudo. Si copiaste .env de otro Mac, revisa sus UID/GID y vuelve a preparar la imagen.

El equipo se queda sin memoria

Ejecuta un escenario a la vez y reduce el tamaño del ejercicio. En Spark puedes elegir el modo ligero. Los límites de los contenedores no son memoria reservada ni garantizan que cualquier trabajo quepa.

Aparecen avisos o contenedores detenidos

Los avisos de Java, SLF4J o módulos opcionales de Hadoop no equivalen a AMD64. En Big Data, hdfs-init, minio-init, retail-init y airflow-init terminan normalmente con Exited (0). Una salida distinta de 0 o un estado unhealthy requiere consultar los registros.

Quiero preparar una clase sin Internet

Construye las imágenes y completa las pruebas con conexión. Los asistentes de inicio usan las imágenes locales. Los ejercicios que descarguen paquetes, datos o extensiones —como httpfs de DuckDB— requieren preparación previa.
